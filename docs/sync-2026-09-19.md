## Existing databases

All normal fetch commands write to the database configured by the user.
To apply the inherited corrections selectively:

```bash
python -m fetch_data.run --source fiscal --series mts
python -m fetch_data.run --source fiscal --series maturity
python -m fetch_data.run --source fred --series fred_gdp
python -m fetch_data.run --source fred --series fred_cpiaucl
python -m fetch_data.run --source fred --series fred_wresbal
python -m fetch_data.run --source nyfed --series repo
python -m fetch_data.run --source pboc --series pboc_omo
python -m fetch_data.run --source pboc --series repo_fixing
python -m fetch_data.run --source nbs --series retail_sales
```

MTS repairs use available API history and preserve older existing records.
The new `pboc_repo_fixing` table is created on its first run. Normal NBS
house-price updates revisit recent history; use a full refresh if an older
installation contains incorrectly assigned city data:

```bash
NBS_HOUSE_FULL=1 python -m fetch_data.run --source nbs --series house_price
```

This upserts the supported 70 cities. It does not delete obsolete city names
that an older installation may already contain; inspect those rows separately.

These commands are instructions for operators; no production database updates
or remote website changes are performed as part of this synchronization.

## Validation and limitations

The data-integrity tests and four public source fixtures come from the website
repository; their provenance is documented in `tests/fixtures/README.md`.
Additional regression tests cover NBS city validation and throttling, FR/FDR
chunk persistence, and series-level status merging. CI installs only the data
pipeline dependencies and runs without database credentials or network fetches.

This is a synchronization of existing source code, not a fresh audit of every
upstream API or every historical observation. In particular, some China
fetchers retain legacy endpoint/TLS workarounds, and policy-rate seed values
require manual maintenance. The hosted website's future maintenance policy
does not disable standalone collection; operators control their own schedules.
